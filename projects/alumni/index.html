01 — Problem

Alumni data goes stale faster than anyone can chase it

Titles, companies, and locations change constantly across hundreds of alumni rows. Keeping the tracker current meant manually searching profile after profile — tedious enough that it simply didn't get done, and the database drifted out of date.

Automating it is easy to get wrong: a naive scraper that overwrites rows on a fuzzy match will corrupt good data. The real problem was doing it conservatively — fast where it's confident, hands-off where it isn't.

02 — Approach

Confidence decides whether the machine or a human writes

Each row runs through the same pipeline, and a confidence score decides what happens next. The default posture is caution: when in doubt, don't touch clean data.

  • Match & scorename · school · dept · companyCandidate profiles are scored on multiple signals, not a single fuzzy name match.
  • High confidence → writescrape & updateCurrent company, role, location, and status are scraped and written — but blank scraped fields never overwrite existing values.
  • Low confidence → reviewhuman gateAmbiguous matches go to a review column instead of overwriting, with row-level notes and a last-checked date for repeatable follow-up.
Design decision — safety first

Dry-run and discover-only modes let you preview every planned write before anything touches the sheet. The pipeline is built to be run repeatedly and conservatively — it would rather do nothing than do harm.

03 — Architecture

A guarded pipeline from sheet to sheet

The tool reads the alumni table from Google Sheets, discovers candidates through configurable search providers, scrapes only the profiles it trusts, and writes back through a confidence gate — recording status, notes, and a timestamp on every row it considers.

04 — What it demonstrates

Automation that knows its own limits

The interesting engineering here isn't scraping — it's restraint: encoding confidence, building review gates and dry runs, and preserving good data by default. It's the judgment that separates automation you can trust from a script that quietly wrecks a database.
